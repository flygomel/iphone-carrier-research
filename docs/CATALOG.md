# Экспериментальный экспорт каталога

Статус: повторные циклы экспорта и возврата прошли на одном исследовательском устройстве после исправления ошибки. Первый вариант с двумя сеансами синхронизации не подтвердил возврат и потребовал восстановления из локальной копии. См. VALIDATION.md. Это не инструкция активации 5G и не read-only операция: исходный каталог временно перемещается в Media, читается и возвращается.

Поддерживаемый исследовательский профиль строго ограничен iPhone18,2 / iOS 27.2 / 24B5084k. Нужны зависимости из README и собранные helpers:

```bash
make -C vendor/airlift
python catalog.py snapshot --confirmed-device-write
```

Не отключайте кабель и не запускайте синхронизацию Books во время операции. Сценарий сохраняет исходное дерево Books, журнал и состояние в `private/catalog-<token>/`; эти материалы содержат личные данные и не предназначены для публикации.

Результат `phase: complete` означает завершение обмена и совпадение дерева Books. **Он ещё не доказывает точный возврат защищённого каталога.** Для этого нужен второй завершённый экспорт и сравнение файлов/ссылок обоих архивов. Поле `protected_readback_verified` поэтому всегда false. ZIP содержит байты файлов и верхние ссылки; права, владельцы, расширенные атрибуты и пустые папки не сериализуются. Это не полный образ файловой системы.

При прерывании не удаляйте папку запуска и не повторяйте snapshot. Восстановление существующего запуска:

```bash
python catalog.py recover --run private/catalog-<token> --confirmed-device-write
```

Замените `<token>` именем конкретной сохранённой папки. Восстановление проверяет устройство и фиксированный целевой путь. Если возврат уже зарегистрирован, сценарий восстанавливает Books и удаляет только созданные временные объекты. Возврат незавершённого экспорта после потери первоначального сеанса не автоматизирован: команда остановится и сохранит данные. Создавать новый сеанс для слепого возврата нельзя.

Неоднозначные состояния — например, исчезнувший экспорт после тайм-аута возврата или сбой первоначальной подготовки — требуют разбора журнала. Скрипт не считает отсутствие экспорта доказательством успешного возврата и не выполняет слепой повтор. При аппаратном сбое оригинальные файлы и ссылки восстановлены вручную из сохранённого ZIP, после чего совпадение подтверждено повторным экспортом. Права, владельцы и расширенные атрибуты отдельно не сравнивались. Это не доказательство автоматического восстановления после любого прерывания.

Команд применения изменённого каталога и установки IPCC здесь пока нет. Не используйте экспорт с другого устройства и не переименовывайте candidate ZIP в IPCC.

## Почему один сеанс

Books-синхронизация может удалять объекты предыдущего набора. Поэтому все три перемещения (ссылка → экспорт → возврат) объявляются заранее в одном сеансе. Помощник останавливается после экспорта; Python читает и проверяет каталог, затем разрешает возврат через тот же процесс. Вспомогательная ссылка перед очисткой должна оставаться символической: если на её месте каталог, очистка прекращается без удаления.
