# Экспериментальный экспорт каталога

Статус: повторные циклы экспорта и возврата прошли на одном исследовательском устройстве после исправления ошибки. Первый вариант с двумя сеансами синхронизации не подтвердил возврат и потребовал восстановления из локальной копии. См. VALIDATION.md. Это не инструкция активации 5G и не read-only операция: исходный каталог временно перемещается в Media, читается и возвращается.

Поддерживаемый исследовательский профиль строго ограничен iPhone18,2 / iOS 27.2 / 24B5084k. Нужны зависимости из README и собранные helpers:

```bash
make -C vendor/airlift
python catalog.py snapshot --confirmed-device-write
```

Не отключайте кабель и не запускайте синхронизацию Books во время операции. Сценарий сохраняет исходное дерево Books, журнал и состояние в `private/catalog-<token>/`; эти материалы содержат личные данные и не предназначены для публикации.

Результат `phase: complete` означает завершение обмена и совпадение дерева Books. **Он ещё не доказывает точный возврат защищённого каталога.** Для этого нужен второй завершённый экспорт и сравнение файлов/ссылок обоих архивов. У обычного snapshot поле `protected_readback_verified` поэтому false; у завершённого восстановления с отдельным совпавшим чтением — true. ZIP содержит байты файлов и верхние ссылки; права, владельцы, расширенные атрибуты и пустые папки не сериализуются. Это не полный образ файловой системы.

При прерывании не удаляйте папку запуска и не повторяйте snapshot. Восстановление существующего запуска:

```bash
python catalog.py recover --run private/catalog-<token> --confirmed-device-write
```

Замените `<token>` именем конкретной сохранённой папки. Восстановление проверяет устройство и фиксированный целевой путь. Если возврат уже зарегистрирован, сценарий восстанавливает Books и удаляет только созданные временные объекты. Если сохранённая копия проверена, восстановление ждёт остановки старого процесса и проверяет защищённый каталог через отдельный сеанс. Сохранённый в Media оригинал возвращается через AirTraffic, после чего выполняется ещё одно защищённое чтение. Неоднозначное состояние без проверенной копии по-прежнему требует разбора; слепого возврата нет.

Сбой подготовки теперь обрабатывается автоматически, если журнал доказывает отсутствие `move_intent`, а перемещённых объектов нет. Обе копии Books сверяются перед записью; после восстановления проверяется полное дерево. Тайм-аут или отмена native-помощника не разрешают очистку, пока его выполнение не закончится. Неоднозначные состояния после отправки команды переноса требуют разбора журнала. Скрипт не считает отсутствие экспорта доказательством успешного возврата и не выполняет слепой повтор. При аппаратном сбое оригинальные файлы и ссылки восстановлены вручную из сохранённого ZIP, после чего совпадение подтверждено повторным экспортом. Права, владельцы и расширенные атрибуты отдельно не сравнивались. Это не доказательство автоматического восстановления после любого прерывания.

Применение и откат доступны в `transaction.py`, установка закреплённых оригинальных IPCC — в `installer.py`; единый запуск описан в README. Не используйте экспорт с другого устройства и не переименовывайте candidate ZIP в IPCC.

## Почему один сеанс

Books-синхронизация может удалять объекты предыдущего набора. Поэтому все три перемещения (ссылка → экспорт → возврат) объявляются заранее в одном сеансе. Помощник останавливается после экспорта; Python читает и проверяет каталог, затем разрешает возврат через тот же процесс. Вспомогательная ссылка перед очисткой должна оставаться символической: если на её месте каталог, очистка прекращается без удаления.

## Подготовка архива для ручного аварийного восстановления

```bash
python recovery_plan.py --run private/catalog-<token> --out private/recovery-plan
```

Эта команда не подключается к телефону. Она проверяет SHA-256 исходного `catalog.zip` по `state.json`, профиль устройства и допустимые пути, затем создаёт `restoration-stage.zip` с Apple mode extra fields. Проверенный локальный результат побайтно совпал с архивом, использованным при успешном ручном восстановлении.

В папке остаётся приватная привязка к устройству. Архив не является IPCC. Команда не проверяет актуальное состояние защищённого пути и не даёт разрешение на его перезапись. Автоматический перенос этого архива после потери исходного сеанса пока не реализован.
