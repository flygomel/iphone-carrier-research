# iPhone Carrier Research — Беларусь

Исследование появления 5G на iPhone 17 Pro Max с A1 и life Беларусь.

**Статус: исследовательский репозиторий, не готовый активатор.** Здесь есть самостоятельная диагностика по USB и проверяемая подготовка файлов на компьютере. Экспериментальный экспорт и возврат каталога проверен на одном устройстве после исправления сбоя; аварийное восстановление потребовало ручной работы. Применение изменённого каталога и полный откат пока не реализованы. Пройти установку «с нуля до 5G» этими командами сейчас нельзя.

Независимый [тест транспорта на случайном файле](docs/CANARY.md) с исходниками AirLift и сохранением резервных копий прошёл на iPhone18,2 / 24B5084k: запись, точное чтение, удаление и возврат отслеживаемых Books sync-файлов подтверждены. Это ещё не тест замены операторского каталога. Порядок оставшихся работ — в [плане релиза](docs/RELEASE-CHECKLIST.md).

## Что получилось

В эксперименте 27 сентября 2026 года:

| Параметр | Значение |
|---|---|
| Телефон | iPhone 17 Pro Max (`iPhone18,2`) |
| iOS / сборка | 27.2 / `24B5084k` |
| A1 | `com.apple.mobilkom_by` 72.7.1, сеть 257-01 |
| life | `com.apple.life_by` 72.7, сеть 257-04 |
| Результат | Меню 5G на обеих SIM; Field Test на life показал NR n7 / 20 МГц |
| A1 в месте проверки | LTE B7, подключение к 5G не подтверждено |

После перезагрузки меню сохранилось. Система снова сообщала штатные операторские пакеты. Точная причина сохранения эффекта и его влияния на life не установлена. Совпадение модели и сборки не является обещанием совместимости или успеха.

## Что понадобится

- Mac и Python 3.12.
- Кабель передачи данных, разблокированный iPhone.
- Доверие между Mac и iPhone, установленное пользователем через Finder / экран телефона.
- Для подготовки офлайн-плана: собственная ранее сохранённая копия каталога операторских пакетов, оригинальный CarrierLab 72.7.1 из подходящей прошивки и отчёт диагностики.

Репозиторий не содержит прошивок, Apple-пакетов, чужих резервных копий, закрытых модулей или персональных идентификаторов. Ничего автоматически не скачивается, кроме зависимостей при явном запуске `pip install`.

## 1. Скачать репозиторий и подготовить Python

На странице GitHub выберите **Code → Download ZIP**, распакуйте архив. Откройте Terminal, напечатайте `cd `, перетащите распакованную папку в окно Terminal и нажмите Enter.

Убедитесь, что доступен Python 3.12:

```bash
python3.12 --version
```

Если команды нет, установите Python 3.12 с [python.org](https://www.python.org/downloads/macos/). Затем:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python carrier.py --help
```

Используется версия pymobiledevice3 11.19.4 из исследовательского окружения. Транзитивные зависимости не зафиксированы: это ещё не полностью воспроизводимая среда установки.

## 2. Проверить подключение без изменения телефона

Подключите ровно один iPhone по USB, разблокируйте его и установите доверие вручную, если Finder предлагает это сделать.

```bash
python carrier.py doctor --out private/device.json
```

Команда только читает модель, версию iOS, сборку, состояние SIM и ограниченный набор сведений об операторских пакетах. Она не создаёт pairing, не устанавливает IPCC и не меняет настройки. UDID, номера телефонов, IMEI, IMSI и ICCID не сохраняются в отчёт.

`matches_research_model_build: true` означает только совпадение модели и сборки с экспериментом. `activation_supported: false` — ожидаемый результат: открытого активатора в репозитории пока нет.

При повторной диагностике выберите новое имя, например `private/device-after.json`: исходный отчёт не перезаписывается. Если iPhone не найден — проверьте кабель, разблокировку и доверие. Ошибка не является основанием менять SIM или сбрасывать настройки сети.

**Для новичка без собственных исходных файлов это текущая точка остановки.** Следующий раздел предназначен для исследователя с ранее полученным экспортом. Экспериментальный сценарий экспорта описан в [CATALOG.md](docs/CATALOG.md); он временно перемещает каталог на телефоне и пока не предназначен для новичков.

## 3. Подготовить файлы на Mac (без записи на iPhone)

Нужны:

```text
private/
  device.json
  baseline-catalog.zip
  CarrierLab.bundle/
    Info.plist
    carrier.plist
    overrides_V53_V54_V57.plist
    overrides_V53_V54_V57.der.pri
    signatures/...
```

`baseline-catalog.zip` — экспорт **своего** исходного каталога, не архив прошивки и не IPCC. На верхнем уровне лежат `*.bundle` и ссылки вида `25701 → mobilkom_by.bundle`. ZIP должен сохранять Unix-тип символических ссылок. В исходном эксперименте каталог к этому моменту уже содержал оригинальные пакеты A1 и Docomo. Нельзя подменять эту предпосылку чужой резервной копией.

Источник CarrierLab — официальная прошивка Apple под нужную модель/сборку. Извлечение и криптографическая проверка происхождения не автоматизированы. Инструмент проверяет структуру и версию, но не удостоверяет Apple-подпись и не доказывает, что предоставленные файлы получены из нужного IPSW.

```bash
python carrier.py plan \
  --baseline private/baseline-catalog.zip \
  --carrierlab private/CarrierLab.bundle \
  --device-report private/device.json \
  --out private/plan
```

Результат:

- `original-catalog.zip` — исходные файлы и ссылки в нормализованном архиве;
- `candidate-catalog.zip` — исходные файлы плюс CarrierLab и новая цель ссылки `25701`;
- `plan.json` — контрольные суммы, манифесты и точное изменение.

Оба архива повторно читаются и сравниваются с ожидаемым содержимым. Старые файлы сохраняются без изменения байтов. Произвольные пути, опасные ссылки и специальные файлы отклоняются. Установка или запись на телефон не выполняется.

**Эти ZIP не являются IPCC: их нельзя передавать установщику приложений.** `original-catalog.zip` — не полная резервная копия iPhone и не проверенный аварийный откат. Свежесть экспорта и его принадлежность подключённому телефону этот офлайн-инструмент не подтверждает.

## 4. Как проходила запись в исходном эксперименте

Этот раздел документирует историю, а не предлагает готовые команды установки:

1. Проверили механизм записи и возврата на отдельном временном объекте.
2. Установили исходный пакет A1 и проверили связь.
3. Проверили экспорт и возврат операторского каталога, сохраняя данные Books.
4. Установили оригинальный Docomo и заново проверили исходный каталог.
5. Добавили оригинальный CarrierLab и изменили только привязку `25701`.
6. Повторным чтением подтвердили все файлы и ссылки.
7. Повторной установкой Docomo вызвали перечитывание.
8. По журналу и метаданным подтвердили выбор CarrierLab для A1.
9. Провели дополнительные проверки; временная правка странового флага не помогла и была регенерирована iOS.
10. После перезагрузки проверили меню, мобильный интернет и Field Test.

Минимальный достаточный набор шагов пока не установлен. Выкинуть пункты и назвать оставшееся воспроизводимой инструкцией нельзя.

Рабочий транспорт зависел от модулей `runtime.pyc` и `core.pyc`, доступных в локальном исследовательском окружении без соответствующих `.py`. Они не включены сюда. В `vendor/airlift` теперь есть открытые исходники низкоуровневого теста под MIT-лицензией; сценарий экспорта и возврата каталога добавлен отдельно и прошёл повторные циклы после исправления ошибки синхронизации. Это ещё не универсальный установщик.

## 5. Проверить результат, если настройки уже применены

1. В настройках сотовой связи выберите нужную SIM для мобильных данных.
2. Отключите Wi-Fi и проверьте интернет.
3. Откройте «Голос и данные» и проверьте наличие 5G.
4. В приложении «Телефон» наберите `*3001#12345#*` и нажмите вызов.
5. Проверьте выбранную линию в Field Test и сохраните сведения о LTE/NR. Параметры могут обновляться с задержкой; один снимок не доказывает постоянную передачу трафика по NR.
6. Проверьте обычные входящие/исходящие звонки отдельно на обеих SIM.
7. После ручной перезагрузки повторите диагностику с новым именем отчёта.

В нашем опыте life показал n7 / 20 МГц / NRARFCN 527070 вместе с LTE B3; A1 — LTE B7. Это наблюдение в конкретном месте и времени, не оценка всей сети A1.

Не публикуйте скриншоты с номером телефона, идентификаторами SIM или неочищенные журналы.

## Восстановление

В исходном опыте сохранялись оригиналы и существовал сценарий штатного возврата после завершённой записи. Аварийное восстановление после прерывания операции не проверено. Команда сброса сети не заявляется способом отката файлов.

Пока независимый транспорт и его восстановление не реализованы и не проверены, в этом репозитории намеренно нет команд `apply`, `install` или `restore`. Это технический пробел, а не требование подписаться или получить пароль.

## Проверки разработки

Без iPhone, сети и pymobiledevice3:

```bash
python3.12 -m unittest discover -s tests -v
```

Тесты проверяют сохранение исходных файлов и ссылок, отказ при неподходящем профиле, обходах путей и дублировании ZIP-записей. Локальные тесты не заменяют проверку на устройстве.

## Что нужно для полноценного релиза

- [ ] Независимый транспорт в читаемых исходниках с известными условиями распространения.
- [ ] Постоянное резервирование, привязка снимка к устройству, защита от устаревшего снимка и журнал каждой операции.
- [ ] Восстановление после обрыва USB, ошибки записи и перезапуска процесса.
- [ ] Проверяемое получение оригинальных пакетов из официальных источников.
- [ ] Повторение полного процесса на исходном состоянии, затем возврат и проверка связи.
- [ ] Проверка после перезагрузки и уточнение причины эффекта на life.
